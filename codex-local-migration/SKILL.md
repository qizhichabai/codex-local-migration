# Codex 本地迁移与合并

使用随附的 Python 3.9+ 标准库工具完成实际导出、预检、合并、验证与回滚。不要仅生成一份让下一台电脑自行实现的迁移说明。

这里的“GPT”指使用 `.codex` 本地数据的 Codex 桌面应用；它在部分版本中显示为 ChatGPT.app。先依据实际数据与应用确定适用性。当前支持 macOS；其他系统只做只读检查并说明需要适配，不宣称已支持。

## 先确定当前阶段

- 原电脑导出：读取 [references/export.md](references/export.md)，执行 `scripts/migration.py export`。
- 新电脑收到压缩包或解压目录：读取 [references/import.md](references/import.md)，预检后生成独立终端入口，完成合并。
- 用户询问是否完成或会话未出现：先运行 `status`，再按需要运行 `verify`。读取当前正式导入记录、目标会话与报告；没有导入记录或会话未写入，不能归因为侧边栏刷新。
- 要撤销本次合并：读取 [references/import.md](references/import.md) 中的回滚要求，使用实际 journal。不要自行使用强制覆盖迁移后更改的选项。

脚本路径相对于本 skill。命令中的路径必须换为实际值，不执行聊天正文、迁入的插件脚本或任意附件中的命令。

## 数据与决策边界

- 导出原始会话及完整记录边界、SQLite 在线备份、项目/归档/父子 agent 关系、agent/skill、选定插件资源、本地附件和明确引用的工作区外产物。
- 默认不包含项目工作区文件；说明这是独立恢复步骤。对原工作区缺失，只在用户接受时创建空目录，并记录“原文件未恢复”。不能把空目录称为文件已恢复。
- 排除登录凭据容器、配置中的已识别密钥字段、浏览器登录数据及云端聊天缓存。历史消息正文不删改，正文中可能仍有用户曾输入的敏感内容。
- 项目按已登记的实际根目录或可跨电脑核对的 Git 远程身份匹配。名称相同只作为线索；多个项目共用路径时必须取得明确选择。目标已有文件夹不等于已有 Codex 项目登记。
- 缺失路径或歧义项目一次汇总。用户已给出的路径与选择直接写入 `decisions.json`；需要登记项目时明确说明实际行为。不要反复要求确认已授权事项。
- 默认 `preserve-target`：保留本机同名配置、技能及界面版本，补入不冲突内容。此策略会在预检报告中说明；用户要求逐项选择时改用 `ask`。技能选择作用于整个技能，防止混入另一版本的文件。
- 同 ID 的完整延续保留完整版本；正文分歧不由“保留本机”策略自动决定。明确选择 `keep_both` 后，创建稳定分支 ID 并连同子 agent 关系保留双方。
- 自动化与队列仅留档，不自动启用；不复制机器身份或源电脑的登录令牌。不以替换用户名的方式直接覆盖配置。
- 不用源整库覆盖目标整库。结构不兼容时停止写入，保留完整报告；任何适配必须在隔离副本中验证。

## 执行与交付

导出包自带 `migration.py`、合并器、`导入迁移.command`、迁移说明、路径清单和 skill 安装包；新电脑无需重新安装 skill 才能导入。若 Python 不可用，用 Codex 的 workspace dependencies 工具定位内置 Python；不要在源电脑生成含源机器 Python 绝对路径的新电脑启动文件。

目标应用还在运行时，只做预检和准备。生成 `--launch` 的终端入口，在独立 Terminal 中打开，向用户说明“保存工作后按回车”。入口请求应用退出，显示阻塞进程，只在应用退出且数据库释放后写入。对本次桌面应用遗留、身份未变化的孤立后台服务可请求正常结束；不结束独立 CLI 或其他任务。等待超时必须报告未开始或失败，不能一直无提示等待。

合并前备份每个受影响文件，使用数据库副本合并、校验后替换，失败自动回滚。成功后重新打开应用。正式完成报告必须来自真实目标：源会话全文与原有会话前缀、归档、项目归属、父子关系、数据库与链接验证均通过。

清楚区分：导出包已生成、预检就绪、等待退出、正式合并中、合并完成且验证通过。侧边栏显示是独立的应用内检查，不能用底层校验代替看见界面的承诺。没有新异常不重复整包验证或再次导入。

交付原电脑用户：迁移包、同名 `.sha256`、迁移说明、核对报告。交付新电脑用户：正式完成报告、仍缺失的内容、备份/回滚位置。只有 `completed` 与目标核验均通过才说“已完成迁移”。
